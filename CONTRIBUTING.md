# Contributing

1. Create `feature/name`, `fix/name`, or `docs/name` from the latest stable `main`.
2. Make focused changes and meaningful commits. Do not commit secrets, generated archives, or machine-specific output.
3. Run the relevant shell syntax checks and behavioral tests.
4. Push the branch and open a pull request describing what, why, and tests.
5. Request review and respond with a follow-up commit. The reviewer checks functionality, organization, documentation, risks, maintainability and security.
6. Re-run checks and merge after approval. Preserve the individual development commits for the assignment.

The author must not present self-review or AI feedback as another student's review. This project is submitted individually: author self-review with Codex assistance is recorded explicitly. No external approval is claimed. The assignment's peer-review requirement remains subject to the instructor's acceptance of this individual format.

Keep `main` stable. Intentional error and conflict exercises belong in `lab/*` branches until corrected and tested. Record their evidence and explanation separately.
